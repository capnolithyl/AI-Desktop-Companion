# Mikan Launcher v0.11.1

**Living reference:** [Feature inventory and verification status](FEATURES.md). Read [launcher maintenance rules](AGENTS.md) before making changes. Update the feature inventory in the same change as every launcher feature, fix or release; distinguish implementation from tested behavior.

Offline-first native Android home app, same package ID and signing key. Optional web shortcut and updater remain independent of core home functions.

## Home pages & folders
Favorites retain their old order; first N valid entries remain dock items, remaining entries flow into 1–4 configurable rows per page. Swipe left/right or tap arrows. Settings > Minimum home pages adds empty pages. Settings > Create app folder picks installed apps, preserving existing shortcuts; folders are additional shortcuts and can be edited, renamed, moved or deleted. Manage favorites and drag onto a visible pinned tile to reorder; cross-page movement via menu. No free-position grid or drag-to-create-folder yet.

## Built-in widgets
Clock, Mikan and music can be assigned to a page or hidden in Settings > Pages & widgets. Third-party Android AppWidget hosting first added in v0.15.1 (managed full-width section; see below); arbitrary pixel placement not supported. Music uses Android MediaSession metadata/album art and supported previous/play/pause/next controls. Enable notification access explicitly under launcher settings. Optional notification dots show active non-ongoing, non-summary notifications (not unread message counts), including folder member notifications. Only app identifiers are retained temporarily in memory; no notification content is stored or transmitted. Android may restrict notification access for sideloaded apps; leave disabled if desired.

## Existing features
Wallpaper, icons, grid/dock sizes, persistent favorites, custom portrait and HTTPS Mikan Web link, signed GitHub release updater. No NAS requirement for core home; configured visible weather may refresh on foreground entry. Other network actions are user initiated. Existing portrait, web address and favorites remain intact on upgrade. Reset portrait returns to default.

## v0.7 dashboard
Weather next to clock, music next to agenda when both share a page and screen/font size permits. Stacked mode selectable; each widget can be hidden or moved independently. Weather uses Open-Meteo (free non-commercial, model-based) and GeoNames geocoding; select city explicitly, no GPS, forecasts fetched only while foregrounded and visible (or explicit refresh); 30-minute cache and stale/offline label. Fahrenheit default, Celsius available. Calendar uses Android CalendarContract.Instances (read-only runtime permission, next seven days, up to two upcoming/ongoing visible instances, no data sent or stored). Calendar titles can be hidden; tap calendar card for calendar app or permission. Verify city selection/units/cache/offline, permission denial/revocation, recurring/all-day events, page pairing and large-font fallback. No Google account credentials required. Existing favorites, art, updater and settings preserved.

## v0.11.4 drawer performance
Replaces the eager all-app ScrollView with native adapter-backed GridView in a constrained viewport. Only needed cells are created/recycled; filtered results update the existing adapter, existing icons and click/long-press actions are preserved, visible badges are rebound and refreshed separately, imported icons refresh in the drawer. No new permissions or dependencies. Performance diagnostics include first/repeat drawer open to pre-draw, setup, filter/submit and individual cell binds. ## v0.11.5 calendar correction
Use Android's documented visible-occurrence query and exclude only explicitly canceled statuses (SQL != previously excluded NULL). Refresh after resume and allow widget long-press refresh/diagnostics. Calendar diagnostics in Weather & calendar settings reports only local/visible calendar counts, occurrence/filter counts and error class; no account names, event titles, or network. Differentiate no local calendars, no visible calendars and no upcoming events. Owner confirmed events now appear after enabling Google Calendar > Settings > General > Share Google Calendar data with other apps and refreshing/synchronizing the calendar. If permission is granted but diagnostics report zero local calendars or occurrences, check that setting and local sync. Additional calendar regression tests remain pending.

## v0.11.6 header system stats
Small two-line RAM and internal data storage used/total indicators in the home header beside Mikan OS, with tap-to-view details and available values. Enabled by default; Settings > Home screen > Header system stats toggles them. Display setting is included in JSON backup. Reads Android MemoryInfo and StatFs asynchronously using existing local worker, throttled to at most one sample per 30 seconds while Home is foregrounded. No new permissions or background service. RAM is total minus Android's available-memory estimate; storage measures the internal data filesystem rather than advertised capacity. Device layout and performance regression pending.

## v0.12.0 quick app search

Tap a result or Go/Enter to launch, close/Back/outside to dismiss. Physical keyboard/IME, layout and performance validation pending. Home editor remains the next phase of v0.12.

## v0.14.2 NAS health remarks
The existing Web reachability setting is renamed NAS health remarks; its preference key is unchanged. GET `/api/health` at the configured HTTPS origin (drops path, query and fragment) instead of HEAD on the UI. The NAS already exposes a minimal read-only `ok`, `service`, `maintenance`, `idle` response before app auth. The launcher validates its identity and Boolean fields and reports idle/busy/maintenance, access protected, missing/unverified endpoint, error or unreachable. Busy may include chat, learning, Brain Lab, knowledge work or writes; not necessarily inference. No provider probing or credentials, no redirects, bounded 4 KiB response, 5s connect/read timeouts, same optional foreground interval/TTL. Manual check under Companion Connection. Keep Beholder loopback port and private Tailscale Serve; do not enable Funnel. No NAS deployment or Pocket login changes necessary. CI/device tests pending.
